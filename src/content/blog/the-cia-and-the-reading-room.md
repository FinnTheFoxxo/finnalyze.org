The United States government is notoriously unreliable at keeping records and is arguably even worse at publishing them. I've spent the last several years archiving data to the best of my ability, and even with all the measures the government takes in an attempt to make data accessible—it's not enough. This is a documentary of my experiences with government data, starting with the Central Intelligence Agency.

The Central Intelligence Agency has one of the largest Freedom of Information Act (FOIA) Reading Rooms of any agency. Considering the fact that it's the CIA and its importance in the history of the United States, its records should hold the same importance. Despite this, its system for storing and presenting these records does not accurately represent said importance.

The CIA FOIA Reading Room contains about a million documents and totals around 500 gibibytes in size. Documents in the Reading Room are for the most part put into relevant categories; a category contains one or more pages, and a page can hold up to twenty documents. Each document on a page is named and enumerated, and the number of pages and the document's stored size are given. Clicking on the document's title redirects you to a page with relevant document metadata and a heading of the document's content. Clicking on the document's file name opens the document directly in a new tab. Many documents are searchable/selectable, but not all of them. In fairness, some documents are so degraded and decrepit that no recognition program could realistically produce a legible output. However, some documents that are crystal-clear are not searchable, while some are borderline illegible and have still gone through a recognition program (and produced garbled output).

With a database that contains so much information, accessibility should be a top priority. The CIA's approach is to allow searching for and downloading specific documents, but not in bulk. The CIA maintains no documented API for the FOIA Reading Room, and as a consequence, you are at the mercy of the CIA's system. This system is unreliable, especially when attempting to access data in bulk; which cannot be done under normal circumstances.

It took me around six months, but I finally managed to download the entirety of the CIA's FOIA Reading Room. In that time, I had to write my own custom script and mold it around the CIA's web architecture to obtain this data, as my go-to tool, wget, was not sufficient. I ended up adding rate limiting to my script to avoid purposefully overloading the CIA's server. Despite this, I often faced days or weeks of halted progress—being provided with 503 and 500 HTTP response codes. One category in the CIA library caused me so much trouble that I ended up going through and downloading each file manually. The "OSS Collection" contains 336 files and is around 10 gibibytes large. The average size of each file in this collection is significantly higher than any other collection. My script could never get through the collection correctly; it would inevitably end up returning HTTP errors. Sometimes it would only fetch one or two documents before the server would return an error. As such, I was left to manually go through the entire web page and download each document by hand. This endeavour took days, as even attempting it manually one file at a time would cause the server to return errors. Eventually, however, after all the struggle and frustration... I succeeded.

The CIA had recently redesigned their Reading Room page. With this redesign came the addition of additional security in the web server. Prior to the redesign, there was no browser-based authentication or verification to assess if a request was automated or not. The redesign added two required session cookies that were required to access content; these cookies could only be reliably obtained with a browser. As such, I had to implement a webdriver into my script to obtain these cookies on the fly per every page, as obtaining them once was not enough as the  cookies would expire. At this point, I had been familiar with web-scraping, but I often relied on wget to do the dirty work for me, and I had little experience with webdriver APIs. Consequently, implementing this took me a bit longer than I would like to admit, that being about a day.

Unfortunately, and as much as it pains me, I am unable to reliably host the data I took from the CIA. I fundamentally believe in the openness of data, especially with an entity as imperative as the federal government. However, my limited internet infrastructure makes it impractical to provide this data. As a compromise, I have decided to [open-source](https://gist.github.com/FinnTheFoxxo/3bb02beaf17046ab06282d65bce54f5c) the code I wrote to perform this archive. The code is being provided as-is, with no guarantee of an update in the event it breaks. To run this script, you'll of course first need to install any needed dependencies. Secondly, to choose what you wish to download, simply replace the URL in the `exec()` function with a category URL from the CIA Reading Room, making sure to leave the needed `{x}` as it controls which page the script will visit. To ensure the script enumerates through every page in the category properly, replace the final number in the `range()` function inside `exec()` with the last page number in the category. Additionally, make sure you create the directories documented in the `open()` function.

In closing, I would like to explicitly express my stance on data in the government. I believe that the government should be mandated to maintain persistent, open access to all data it produces—whether in bulk or in small quantities. Access to this data should remain permanent; it should not be monetized and should be anonymous; data should never be altered or removed; data should only be added.
